1. 通过EditorView 中的docViewDesc将doc:Node 转换为真实的DOM节点
2. 最终渲染
  - 在tiptap中，通过editor-content将tiptap Editor 的element 的childNodes(EditorView的this.dom)  append到页面中
  - 在单纯的prosemirror项目中，构建EditorView时，直接传递一个element，用来挂在EditorView的this.dom元素

# ViewTreeUpdater 视图树更新器
## 作用
它的主要职责是作为一个 状态机/游标 ，帮助 updateChildren 在遍历新的子节点数据（ node.content 和 decorations ）时：
1. 记录当前对比到了旧的 children 数组的哪个位置（ updater.index ）。
2. 维护当前处理到了哪一层 Mark 嵌套栈（ updater.stack ）。
3. 记录这次更新是否真的发生了变化（ updater.changed ）。
4. 提供一系列增量更新的策略方法（ findNodeMatch 、 updateNextNode 、 addNode 等）。



```ts

// 视图树更新器；用来diff旧的ViewDesc和新的ViewDesc；并尽量复用已有的ViewDesc对象
// 这个updater是个短期的辅助对象，只在updateChildren函数的执行过程
// 每个层级的NodeViewDesc updateChildren的时候，都会创建一个updater，用于处理当前层的子节点更新
class ViewTreeUpdater{
  // 当前处理到了旧的 children 数组的哪个位置
  index = 0
  // 栈，用来记录当前处理到了哪一层 Mark 嵌套栈 ?
  stack: Mark[] = []
  // 记录这次更新是否真的发生了变化 ?
  changed = false
  // 顶部节点视图描述器
  top:NodeViewDesc


}

```



每个Node就会转换为一个NodeViewDesc对象
每个NodeViewDesc在updateChildren的时候，会创建一个ViewTreeUpdater对象

# 总结
1. doc：Promsemirror通过将文本内容，转换后输出的Node树状结构
2. 根据editorView的doc: Node，在docViewDesc方法中，生成一个NodeViewDesc对象
3. nodeViewDesc.updateChildren()时，会在iterDeco中递归doc:Node的所有child 并通过(ViewTreeUpdater).addNode 来创建下级Node节点的NodeViewDesc对象
4. 如果还有下级，继续递归处理；最后形成NodeViewDesc的层级树结构(但不是在形成数之后再去做节点渲染)
5. 在递归的过程中，在达到最末级节点时；通过renderDescs方法，将当前NodeDescView的children，依次挂载到当前NodeDescView的dom节点上
6. 递归处理完，editorView.dom 上就包含了所有节点
7. 而editorView.dom，会被挂在到需要渲染的节点上(例如：tiptap的editor-content、或者单纯的prosemirror项目中，直接传递一个element，用来挂在EditorView的this.dom元素)
