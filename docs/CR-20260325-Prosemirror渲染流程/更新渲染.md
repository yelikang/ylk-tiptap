# 更新渲染流程
## 路径A(更'命令式'):
   - 通过initInput监听到keypress事件，获取到输入的字符
   - 直接把字符转换成transaction并dispatch  view.dispatch(view.state.tr.inserText(text).scrorllIntoView())
> 这条路的本质是： 事件 -> 生成tr(insertText) -> dispatch -> state.apply -> view.updateState -> DOM更新

## 路径B(更 '声明书/兼容性更强' —— 主要使用):
   - 浏览器先修改，然后通过DOMObserver监听到dom变化，进入DOMOBserver.flush
   - flush汇总 "文档哪段DOM变脏了"，然后调用readDOMChange(构造DOMObserver时的回调函数)
   - 在readDOMChange中，根据DOM变化，生成transaction，dispatch到view.dispatch

> 本质: 浏览器先插字 -> 触发Mutation -> PM解析DOM变化 -> 生成tr -> 更新state -> PM再把DOM调整成与state完全一致的样子
> 看起来像DOM先变，又被PM改回来



## Transaction —— 事务
定义:
 对文档变更的可组合操作容器;

Step概念
 - tr是从当前state派生出来的： view.state.tr
 - 进行tr.insertText操作时，改变的时transaction对象本身：它会累计steps，并且tr.doc会变成 "应用这些steps后的文档"；但这时view.state还是旧的
 - 调用dispatch(tr)，this.state.apply(tr)会根据tr更新state，返回一个新的state
 - 调用dispatch(tr)，this.updateState会把view.state赋值成这个新的state，并触发DOM更新的state

class EditorState{
  config: Configuration
  selection: Selection
  get plugins: this.config.plugins
  get tr: new Transaction(this)

  state: EditorState
  curSelection:  state.selection
